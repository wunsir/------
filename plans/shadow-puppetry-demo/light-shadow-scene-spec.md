# light-shadow 王牌页首屏高潮交互规格（L1 一束灯控制一位影）

## 范围与边界
- 本文档只覆盖 light-shadow 页面。
- 本文档只定义交互规格与结构规格，不包含实现代码。
- 本文档不涉及首页 opening，也不涉及 craft / reborn 重写。
- 本文档用于直接指导后续实现与测试验收。

## 1. 目标
- 建立单一强记忆点：用户在首屏只记住一件事，移动一束灯，就能立刻改变一个影人的戏感。
- 把首屏交互从“看内容”升级为“操一场戏”：输入和反馈必须实时、连续、可预期。
- 明确三端行为：桌面鼠标、移动触摸、无交互设备 fallback 都能理解同一套光影关系。
- 固定后续叙事顺序，避免回退为均匀 section 堆叠。

## 2. 王牌页在整站中的职责
- 这页是整站高潮页，视觉与交互强度必须明显高于首页、craft、reborn。
- 这页承担“把皮影最迷人的关系说清楚”的职责：光、幕、影、人如何互相决定。
- 这页不是信息总览页，不以卡片数量取胜，而以单场景强体验取胜。
- 这页首屏完成情绪峰值，后续模块负责解释与延展，不再争抢主舞台。

## 3. 首屏单一记忆点定义
### 3.1 记忆点句子
- 用户离开首屏后应能复述：我刚才在移动一束灯，影人的影子和气质马上变了。

### 3.2 单一性原则
- 单舞台：只有一块纸幕作为观看面。
- 单主角：同一时刻只出现一位影人。
- 单控制：只允许“灯位变化”作为首屏核心交互。
- 单后果：所有视觉变化都必须被解释为灯位变化的结果。

### 3.3 失效判定
出现以下任一情况，视为记忆点失效：
- 首屏同时出现多个可竞争焦点（多卡片、多入口、多主按钮）。
- 用户输入与视觉变化关系不清（移动了但看不出为什么变化）。
- 反馈只在局部生效（例如只有光斑动，影与空间关系不动）。

## 4. 首屏视觉组成
首屏视觉组成只能围绕以下四项，不增加平级视觉主角：
- 纸幕
- 影人
- 一束灯
- 暗场

### 4.1 分层关系（从后到前）
- 暗场：整屏基底，负责收光与聚焦，压住无关信息。
- 纸幕：主要受光平面，承担光斑、亮度梯度、影像投射。
- 影人：唯一角色剪影，提供轮廓识别与动作性格。
- 一束灯：由光源方向、光束路径、光斑落点组成，统一驱动视觉变化。

### 4.2 首屏限制
- 首屏内不放三段式卡片阵列。
- 首屏内不放与主交互同权重的说明模块。
- 首屏文案只保留开场句与最短操作提示，避免信息句抢焦点。

## 5. 交互输入模型
### 5.1 统一输入抽象
统一为“光位目标点”模型，记为 L(u, v)：
- u：横向归一化坐标，范围 0 到 1。
- v：纵向归一化坐标，范围 0 到 1。

无论鼠标还是触摸，都先转换为 L(u, v)，再驱动同一套光影反馈规则。

### 5.2 输入状态机
- idle：未输入，舞台保持轻呼吸。
- tracking：检测到鼠标移动或手指拖动，实时更新 L(u, v)。
- settle：输入结束后，灯位缓停到最近稳定构图位。
- auto-demo：无交互设备或长时间无输入时，自动演示灯位路径。

### 5.3 输入与滚动冲突规则
- 桌面端：鼠标移动只影响首屏光位，不劫持页面滚动。
- 移动端：只在首屏交互区域内启用拖动控灯；滑出区域后恢复正常纵向滚动。
- 任一端均不得出现“轻触即误滚”或“想滚动却被强行拖灯”的冲突。

## 6. 光位与视觉反馈联动规则
灯位变化必须同时覆盖以下五类反馈：
- 光斑
- 影子
- 轮廓
- 亮度
- 空间前后关系

### 6.1 联动矩阵
| 反馈维度 | 必须发生的变化 | 用户可感知结果 |
|---|---|---|
| 光斑 | 光斑中心跟随 L(u, v) 移动；半径与边缘软硬随灯位变化 | 用户清楚看到“灯在幕上走” |
| 影子 | 影子方向与灯位方向形成反向关系；长度随灯位偏移变化 | 用户清楚看到“影被灯推着变” |
| 轮廓 | 轮廓清晰度在不同灯位区间变化（清晰 / 过渡 / 柔化） | 用户感到人物在“被点亮”而非纯贴图 |
| 亮度 | 纸幕亮度梯度与角色受光强度同步变化 | 用户能区分主光区与暗区 |
| 空间前后关系 | 通过影形大小、偏移、叠压关系表达“前后距离” | 用户能读出舞台深度，不是平面拼贴 |

### 6.2 构图优先级
- 第一优先：影人轮廓可读。
- 第二优先：灯位变化连续。
- 第三优先：光斑氛围细节。

当设备性能不足时，优先保住前两项。

### 6.3 戏剧区间
将灯位划分为三个戏剧区间，便于实现与测试：
- 中位区：叙事最稳，轮廓最清晰，用于默认展示。
- 偏位区：影子拉伸明显，动作感增强，用于“起势”。
- 极位区：亮度与轮廓对比最强，用于短时强调，不做常驻。

## 7. 桌面端行为
- 首屏进入后默认落在中位区，用户一移动鼠标即进入 tracking。
- 鼠标持续移动时，灯位连续更新，反馈延迟应保持在可感知实时范围。
- 鼠标离开首屏交互区域后进入 settle，不瞬间跳回初始位。
- 桌面端筛选入口以“换人物上场”方式贴近主舞台，不再独立成大段筛选卡区。
- 在首屏未滚出前，桌面端视觉重心必须始终锁定主舞台。

## 8. 移动端行为
- 首屏默认显示中位区构图，并提供一次性短提示：按住幕面移动灯位。
- 单指拖动映射为 L(u, v)，多指输入仅跟随第一触点。
- 手指抬起后进入 settle，保持短暂余韵再稳定。
- 当用户执行明显纵向浏览意图时，立即让出滚动控制。
- 移动端首屏文案量比桌面更少，保证小屏不拥挤、不遮挡纸幕与影人。

## 9. fallback 行为
### 9.1 触发条件
满足任一条件即进入 fallback：
- 无可用鼠标与触摸输入。
- 运行环境不支持连续指针事件。
- 用户偏好降低动态效果或设备性能不足以支撑实时联动。

### 9.2 fallback 表现
- 自动演示固定灯位路径：左偏位 -> 中位 -> 右偏位 -> 中位。
- 每个关键帧至少让用户看清五类反馈中的三类联动变化。
- 页面仍保持“纸幕 / 影人 / 一束灯 / 暗场”四要素，不退化成静态图文堆叠。
- 提供一句简短解释，确保无交互时也能理解“灯位决定影感”。

### 9.3 可理解性底线
即使用户完全不操作，也必须在一个自动循环内看懂：
- 灯位变了。
- 影子方向和轮廓跟着变了。
- 这就是一场戏的核心机制。

## 10. 首屏之后的内容结构重排
后续结构顺序固定，不可打乱，不可回退为均匀 section 堆叠：
- 主高潮交互
- 幕布之后的操演逻辑
- 剧目舞台瞬间
- 一场戏如何成立的时间线

### 10.1 模块关系要求
- 第二段（幕布之后）紧接首屏，用于解释操杆、提腕、停顿如何与灯位共振。
- 第三段（剧目瞬间）作为案例放大镜，展示不同人物或剧目的舞台片刻。
- 第四段（时间线）负责收束，回答“一场戏如何成立”。

### 10.2 反模板化要求
- 四段在版式高度、节奏密度、动效语义上必须有明确差异。
- 禁止四段都使用同一容器样式、同一标题结构、同一入场动效。
- 首屏动效强度最高，后续逐步克制，但信息可读性持续上升。

## 11. 筛选如何转为“换人物上场”
### 11.1 交互语义改写
- 旧语义：筛选卡片。
- 新语义：换人物上场。

### 11.2 行为流程
- 用户选择角色类型或具体角色。
- 当前影人先完成退场（收光或侧退）。
- 新影人完成上场（入光、立轮廓、定姿）。
- 灯位控制权立即回到用户当前输入，不重置交互心智。

### 11.3 数据联动要求
- 主舞台角色、剧目瞬间推荐、时间线提示可随上场人物联动更新。
- 不再以大网格卡片淡入淡出作为主要反馈。

## 12. 建议新增的页面私有组件
仅建议组件职责，不涉及实现代码：
- LightShadowSceneShell：页面总容器，编排四段固定顺序。
- L1HeroStage：首屏舞台，承载四要素与核心交互。
- LampInputSurface：输入采样与统一坐标映射。
- PuppetStageActor：单影人渲染与上场/退场编排。
- CharacterOnStageSwitcher：把“筛选”转译为“换人上场”的控制条。
- BackstageMechanicsSection：幕布之后的操演逻辑展示。
- StageMomentSection：剧目舞台瞬间展示。
- PerformanceTimelineSection：一场戏成立时间线展示。
- SceneFallbackPlayer：无交互设备自动演示与说明。

## 13. 建议新增的交互状态
仅定义状态语义，不绑定具体框架：
- activeCharacterId：当前上场人物。
- scenePhase：opening / interactive / switching / settle / auto-demo。
- inputMode：mouse / touch / none。
- lampTarget：输入目标灯位。
- lampRender：经过缓动后的实际灯位。
- lightingMetrics：光斑、影子、轮廓、亮度、空间关系的派生指标集合。
- isFallback：是否处于 fallback。
- motionLevel：常规动态或降级动态。

状态转换关键约束：
- switching 期间仍需保持四要素可读，不允许黑屏断层。
- fallback 与 interactive 可双向切换，切换时不出现灯位突跳。
- 任何状态下都要保证“一束灯控制一位影”的叙事不丢失。

## 14. 测试与验收标准
### 14.1 首屏核心验收
- 用户在 5 秒内能发现唯一主交互是控灯位。
- 控灯后，五类反馈均可见且方向关系正确。
- 角色始终保持单主角，不出现并列主角争抢焦点。

### 14.2 桌面端验收
- 鼠标移动可稳定驱动灯位，离开后平滑 settle。
- 首屏滚动不被错误拦截。
- 换人物上场动作连续，不出现突兀闪烁或重置错位。

### 14.3 移动端验收
- 单指拖动可控，抬手后平滑回稳。
- 与纵向滚动冲突可控，用户能顺畅继续浏览后续结构。
- 小屏下首屏文字不压住纸幕关键区域。

### 14.4 fallback 验收
- 无交互输入时，自动演示仍可解释灯位与影感关系。
- 降级模式下仍保留四要素与固定结构顺序。
- 不因降级而退化成普通多 section 展示页。

### 14.5 结构顺序验收
页面结构必须严格为：
- 主高潮交互
- 幕布之后的操演逻辑
- 剧目舞台瞬间
- 一场戏如何成立的时间线

任何与上述顺序冲突的实现均判定为不通过。

### 14.6 站内定位验收
- light-shadow 的首屏强度、空间感、交互记忆点必须明显高于其余三页。
- craft / reborn 保持支撑页定位，不与本页首屏争夺高潮角色。
