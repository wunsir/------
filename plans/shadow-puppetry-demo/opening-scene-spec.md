# `一戏入影` 首页 Opening 场景规格

## 范围说明

本文只定义首页 opening 场景的实现规格，用于指导后续首页重做。

本文不覆盖：

- `light-shadow` 首屏交互设计
- `craft / reborn` 内容结构重写
- 全站通用动效系统的完整实现方案

本文默认遵循现有整站边界：

- 保留四路由结构与导航顺序
- 首页导览顺序固定为 `光影美学 -> 制作工艺 -> 当代新生`
- opening 完成前，导览和解释信息不能抢主视觉
- 首页不是百科首页，也不是信息总览页
- 不接真实音频
- 允许新增首页 page-specific components，不强行复用当前 Hero 模板

## 1. 目标

首页 opening 的目标不是介绍网站结构，而是先把用户带进一场戏的开头。

必须同时做到：

- 在 `3.8s - 5.2s` 内建立“幕布、戏台、暖灯、影人”四个核心记忆点
- 让 opening 的最后一帧直接成为首页首屏，而不是播完再切回另一套 Hero
- 把导览入口延后到仪式完成之后再出现
- 给后续实现窗口一套不用再猜的时间、层级、显隐和降级规则

## 2. 首页在整站叙事中的职责

首页是整站的 `开场导演页`，职责只有三件事：

- 把用户从站外浏览状态拉进戏台情境
- 把整站主叙事交给 `光影美学`，而不是在首页抢高潮
- 在 opening 结束后，用展陈式导览把用户送往固定顺序的三个分主题

首页不承担的职责：

- 不在首屏堆叠解释性文案
- 不在 opening 前展示完整导航、CTA、说明段落
- 不把三个分主题做成普通信息卡列表

## 3. 视觉基调

opening 视觉必须像 `暗场戏台的开幕瞬间`，不是常规网页 Hero。

核心视觉对象：

- `幕布`：深酒红，厚重，有竖向褶纹，但不要写实到舞美照片感
- `戏台`：以纸幕、檐口、台口、前沿台板构成简化戏台，不做复杂建筑细节
- `暖灯`：偏钨丝暖金，不是白色聚光灯，也不是霓虹光
- `影人`：以剪影和局部镂空感呈现，优先表现头饰、袖摆、操杆和关节轮廓

视觉原则：

- 开场前半段以 `暗` 为主，亮部面积严格受控
- 光只负责把戏台和影人点活，不负责照亮整个页面
- 画面前半段不出现大段文案，不出现“网页感”的按钮组
- 最终首屏仍然保留黑场和负空间，让 `light-shadow` 继续做全站最高峰

## 4. 分镜序列

opening 使用固定六段分镜，顺序不可改。

### 4.1 闭幕状态

目标：

- 让用户先进入“戏未开场”的等待状态

画面规格：

- 首屏初始为近全黑舞台，中央有明显但克制的幕布中缝
- 幕布覆盖舞台主体，纸幕、影人、导览卡、导航均不可见
- 仅允许极轻的环境呼吸感，不允许先看到解释文案

时长：

- 桌面端完整版：`0ms - 600ms`
- 移动端完整版：`0ms - 420ms`
- 回访缩短版：`0ms - 220ms`

禁止项：

- 禁止完整 header 先出现
- 禁止三张导览卡先占位
- 禁止用副标题代替场景建立氛围

### 4.2 幕布中缝被拉开

目标：

- 用一个明确动作告诉用户“戏要开了”

画面规格：

- 幕布从中缝向左右拉开，不做真实拖拽交互，但要保留被拉开的机械感
- 中缝先细后宽，左右帘边有轻微滞后与回弹
- 中缝后只露出局部纸幕和极弱暖色，不提前完整暴露舞台

时长：

- 桌面端完整版：`600ms - 1800ms`
- 移动端完整版：`420ms - 1280ms`
- 回访缩短版：`220ms - 700ms`

出画要求：

- 幕布打开至约 `62% - 70%` 时进入下一阶段，不需要完全退场
- 两侧幕布在后续阶段继续留在屏幕边缘，作为戏台边框的一部分

### 4.3 戏台显现

目标：

- 把“网页首屏”转换成“戏台内部空间”

画面规格：

- 纸幕、台口、前沿台板、上檐轮廓逐步显现
- 纸幕亮度先低后高，初始只够看出层次，不够看清主体
- 戏台出现方式以 `从暗中浮现` 为主，不做大幅飞入

时长：

- 桌面端完整版：`1800ms - 2600ms`
- 移动端完整版：`1280ms - 1900ms`
- 回访缩短版：`700ms - 980ms`

构图要求：

- 桌面端戏台主体居中，占首屏宽度约 `58% - 68%`
- 移动端戏台主体居中，占首屏宽度约 `78% - 86%`
- 首屏上下保留暗场余量，避免画面被 UI 填满

### 4.4 暖灯点起

目标：

- 用光把视觉重心从幕布动作转到纸幕和舞台核心

画面规格：

- 暖灯从纸幕上方中央偏后的位置点起
- 光感先是一个受控光核，再扩成柔和椭圆光晕
- 灯亮时允许出现非常轻的亮度脉冲，模拟灯刚被点起，不做夸张闪烁

时长：

- 桌面端完整版：`2400ms - 3200ms`
- 移动端完整版：`1760ms - 2440ms`
- 回访缩短版：`860ms - 1120ms`

亮度约束：

- 暖灯只照亮戏台中央，不得把背景整体洗白
- 屏幕最亮点必须始终在纸幕或影人附近，而不是落在导航或卡片上

### 4.5 影人登场

目标：

- 给首页一个明确的“主角到场”瞬间

画面规格：

- 影人从舞台侧后方或下方进入，最终停在纸幕中轴略偏左或略偏右的位置
- 入场必须有方向性，不能直接静态出现
- 影人最终姿态为 `已入戏但未开打`，更像亮相，不像高潮动作
- 入场结束后保留极轻微的 idle 摆动，像操杆在手里还没完全停下

时长：

- 桌面端完整版：`3200ms - 4300ms`
- 移动端完整版：`2440ms - 3200ms`
- 回访缩短版：`980ms - 1320ms`

主体约束：

- 影人轮廓优先清晰于材质细节
- 影人尺寸不能大到压过戏台结构
- 首页影人不应比 `light-shadow` 首屏更强、更近、更具操控感

### 4.6 导览卡与导航出现

目标：

- 把用户从“看开场”平滑交给“开始浏览”

画面规格：

- 导航与导览卡只在影人完成亮相后出现
- 导航先出现，导览卡后出现，两者都不能和影人抢同一时刻的注意力
- 三张导览卡按固定顺序进入：`光影美学 -> 制作工艺 -> 当代新生`
- 卡片不是普通信息卡列表，而是展陈入口板，视觉气质必须有差异

时长：

- 桌面端完整版：`4300ms - 5200ms`
- 移动端完整版：`3200ms - 3980ms`
- 回访缩短版：`1320ms - 1680ms`

结束条件：

- 当导航可操作、导览卡可操作、影人进入 idle 状态时，首页进入 `ready`

## 5. 状态机 / 播放阶段

首页 opening 需要显式状态机，不能只靠一串零散动画开关。

建议状态枚举：

- `boot`
- `opening-full-closed`
- `opening-full-curtain`
- `opening-full-stage`
- `opening-full-light`
- `opening-full-puppet`
- `opening-full-handoff`
- `opening-short-curtain`
- `opening-short-light`
- `opening-short-handoff`
- `ready`
- `ready-static`

状态规则：

- `boot`：页面刚挂载，尚未判定播放策略
- `opening-full-*`：首次进入完整版的连续阶段
- `opening-short-*`：站内回访缩短版的连续阶段
- `ready`：首页完整可交互态，保留 idle 动效
- `ready-static`：用于 reduced motion 或动画条件不足的静态就绪态

转移规则：

- `boot -> opening-full-closed`：满足首次进入条件时
- `boot -> opening-short-curtain`：满足站内回访条件时
- `boot -> ready-static`：满足 fallback 条件时
- `opening-full-handoff -> ready`
- `opening-short-handoff -> ready`
- 任意 opening 状态收到 `skipRequested` 后，直接补齐必要显隐并进入 `ready`

状态持久化建议：

- 用 `sessionStorage` 或等价会话状态记录 `hasSeenHomeOpening`
- 记录 `lastHomeReadyAt`
- 记录 `lastHomeExitAt`
- 不需要跨设备或长期持久化

## 6. 首次进入规则

首次进入必须播放完整版，但仅限 `当前站内会话的第一次完整进入首页`。

判定条件：

- 当前路径为 `/`
- 当前会话内不存在 `hasSeenHomeOpening = true`
- 未触发 reduced motion
- 未触发低性能或降级策略

完整版规则：

- 必须完整覆盖六段分镜
- opening 总时长桌面端控制在 `5.2s` 内
- opening 总时长移动端控制在 `4.0s` 内
- 完整版中不出现首屏解释段落和普通 CTA
- 完整版播完后，最后一帧直接停留为首页首屏，不再切换到另一种布局

完成时机：

- 首页首次进入完成后，立即写入 `hasSeenHomeOpening = true`
- 同时写入 `lastHomeReadyAt = now`

可跳过规则：

- 完整版允许用户在播放 `1.2s` 后触发跳过
- 跳过方式可接受 `点击 / 轻触 / 滚动 / Esc`
- 跳过后必须直接进入 `ready`，但仍保持“幕已开、灯已亮、影人已在场”的最终构图

## 7. 回访缩短版规则

站内回到首页时，不再重播完整版，只播缩短版或直接就绪。

触发场景：

- 用户从 `craft / light-shadow / reborn` 返回首页
- 用户刷新首页但当前会话已看过完整版
- 用户在首页与其他页面之间快速切换

缩短版规则：

- 不再从全闭幕开始讲完整故事
- 以 `半闭幕提示 -> 快速开幕 -> 灯已接通 -> 影人已在位 -> 导览回场` 为主
- 桌面端总时长控制在 `1.4s - 1.8s`
- 移动端总时长控制在 `1.1s - 1.5s`

进一步缩短规则：

- 如果 `now - lastHomeExitAt < 15s`，允许直接跳过缩短版，进入 `ready`
- 如果用户在缩短版期间再次返回首页，直接进入 `ready`
- 如果用户使用浏览器返回并期望快速继续浏览，不应再次被完整仪式打断

缩短版仍需保留的记忆点：

- 至少保留一次“幕已被拉开”的提示
- 至少保留暖灯与影人的组合构图
- 导览卡仍按固定顺序出现

## 8. 桌面端行为

桌面端首页 opening 采用 `宽戏台 + 上层导航 + 下层导览板` 的三层构图。

行为规格：

- 首屏以 `100svh` 为基准，高度不足时允许压缩边缘留白，不允许把导览卡挤到第二屏才可见
- 开场阶段主视觉区保持居中，横向重心稳定，不做全屏追光式镜头运动
- 导航在 `handoff` 阶段从顶部轻移入场，使用低位移、低透明渐入
- 三张导览卡在 `handoff` 阶段从下方向上入场，按固定顺序错峰 `80ms - 120ms`
- 卡片正文首屏只保留必要信息：标题、一句场景句、进入动作

桌面端构图建议：

- 顶部：品牌锁定与四路由导航
- 中部：戏台、暖灯、影人，保持主视觉
- 底部：三张导览卡，占首屏下缘，但不遮住影人核心轮廓

桌面端禁止项：

- 禁止把三张卡片做成均质化 hover 浮起模板
- 禁止在 opening 未完成时把 sticky header 先顶出来
- 禁止首页出现现成 Hero 的左右分栏文案布局

## 9. 移动端行为

移动端必须简化层次，但不能失去“开幕仪式”。

移动端简化原则：

- 保留六段顺序，但合并细碎过渡
- 减少舞台边缘装饰，保留 `幕布 / 纸幕 / 暖灯 / 影人`
- 把导航压缩为 `品牌 + 菜单入口`，而不是完整横向路由排布

移动端 opening 规格：

- 首屏主视觉高度约占 `62svh - 68svh`
- 幕布拉开幅度比桌面更直接，避免窄屏上层次过碎
- 影人入场路径更短，以免在小屏上显得拖沓
- 导览卡改为纵向堆叠或可滑动短卡，不使用三列并排
- 每张导览卡只保留 `主题名 + 一句场景句 + 进入提示`

移动端导航规则：

- opening 期间隐藏完整导航
- `handoff` 阶段先出现品牌，再出现菜单按钮
- 菜单列表可在用户主动触发后展开，不要求与 opening 同时全量出现

移动端禁止项：

- 禁止首屏同时出现过多说明文本
- 禁止为了适配而删掉影人登场
- 禁止用普通 banner 替代戏台构图

## 10. fallback 行为

opening 必须有明确降级方案，不能把体验建立在“所有设备都跑得动”之上。

### Reduced Motion

触发条件：

- `prefers-reduced-motion: reduce`

行为：

- 不播放分镜动画
- 直接进入 `ready-static`
- 首屏默认呈现 `幕已开、灯已亮、影人已在位、导览与导航已可用` 的静态构图
- 允许极轻的 opacity 显示，但不允许明显位移和缩放

### 低性能 / 动画条件不足

触发条件建议：

- 首屏关键动画检测为低能力模式
- 首次渲染明显掉帧
- 设备环境不适合多层 blur / mask / clip-path

行为：

- 改用 `lite` 版本 opening
- 删除复杂幕布回弹和细小光晕脉冲
- 影人可直接以最终姿态出现，只保留 `灯亮 + 导览回场`
- 总时长控制在 `900ms - 1400ms`

### 快速返回首页

触发条件：

- 用户离开首页后很快返回
- 用户连续多次切换首页与子页

行为：

- 优先直接进入 `ready`
- 只允许导航或导览卡做一次极轻的重新显现
- 不再重新执行“闭幕 -> 拉幕”完整链路

### 资源或状态异常

触发条件：

- opening 中途状态丢失
- 动画未完成但页面已可交互

行为：

- 强制补齐到最终首屏构图
- 确保导航、导览、影人、暖灯都处于一致的 ready 状态
- 不允许页面停在“半开幕但无导览”的悬空状态

## 11. 导览与导航出现时机

导览和导航必须服从 opening 主视觉，不可抢拍。

固定规则：

- `闭幕状态` 到 `影人登场` 结束前，导航不可操作
- `闭幕状态` 到 `影人登场` 结束前，导览卡不可见
- `闭幕状态` 到 `ready` 之前，现有全局 footer 不进入首屏视口
- 导航先出现，导览卡后出现
- 导航与导览的出现都必须发生在影人已停止主运动之后

桌面端推荐时序：

- `影人完成亮相 + 80ms`：品牌与导航开始显现
- `导航开始后 + 140ms`：三张导览卡依序显现
- `第三张卡出现后 + 120ms`：首页进入 `ready`

移动端推荐时序：

- `影人完成亮相 + 60ms`：品牌出现
- `品牌出现后 + 120ms`：菜单入口出现
- `菜单入口出现后 + 100ms`：导览卡从下方回场

导览卡内容约束：

- 首屏卡片不得出现长段信息说明
- 卡片标题顺序固定为 `光影美学 / 制作工艺 / 当代新生`
- `光影美学` 卡在视觉上可以略更强，但不能强到盖过戏台主体

## 12. 页面结构建议

首页首屏不应继续使用当前 `PageHero + SectionBlock + ThemeLinkCard` 组合。

建议结构：

```text
HomePage
  HomeOpeningScene
    HomeStageViewport
      HomeCurtainLayer
      HomeStageSet
      HomeWarmLight
      HomePuppetFigure
      HomeNavOverlay
      HomeGuideDeck
  HomeAfterstageSection
```

结构原则：

- opening 场景本身就是首页首屏
- 首屏所有对象围绕同一个戏台空间构图
- 导航和导览属于 opening 的后半段层，不是独立于 opening 之外的另一个版头和卡片区
- below the fold 内容如保留，必须从 opening 首屏之后开始，且不得改变首屏构图与入场节奏

当前结构中不建议复用到首页首屏的部分：

- `PageHero` 的左右分栏 Hero 结构
- `SectionBlock` 的标准章节容器首屏用法
- `ThemeLinkCard` 的统一 hover 卡片语言
- `StageLayout` 当前“进入页面即显示完整 sticky header”的首页首屏行为
- `StageLayout` 当前默认可见的首页 footer 首屏行为

## 13. 建议新增的页面私有组件

建议新增以下首页私有组件或等价模块：

- `HomeOpeningScene`
  - 首页 opening 的总编排容器，负责阶段切换与显隐协调
- `HomeCurtainLayer`
  - 负责闭幕、拉幕、中缝、边帘残留状态
- `HomeStageSet`
  - 负责纸幕、台口、前沿台板、背景暗场
- `HomeWarmLight`
  - 负责暖灯点亮、光晕范围、亮度约束
- `HomePuppetFigure`
  - 负责影人入场、停驻姿态、idle 摆动
- `HomeNavOverlay`
  - 负责首页专属导航入场，不复用“页面一加载就露出”的 header 行为
- `HomeGuideDeck`
  - 负责三张导览入口的顺序、节奏和差异化视觉
- `HomeOpeningFallback`
  - 负责 reduced motion、lite 模式、异常补齐

## 14. 建议新增的交互状态

建议至少显式管理以下状态：

- `openingMode`
  - 值建议：`full | short | lite | static`
- `scenePhase`
  - 值建议：`closed | curtain | stage | light | puppet | handoff | ready`
- `hasSeenHomeOpening`
  - 当前会话是否已完成完整版
- `lastHomeReadyAt`
  - 上一次首页进入 ready 的时间
- `lastHomeExitAt`
  - 上一次离开首页的时间
- `skipRequested`
  - 用户是否请求跳过 opening
- `navVisible`
  - 导航是否允许显现和交互
- `guideVisible`
  - 导览卡是否允许显现和交互
- `puppetPose`
  - 值建议：`hidden | entering | settled | idle`
- `animationCapability`
  - 值建议：`full | lite | static`

状态原则：

- `scenePhase` 是主状态，其他显隐状态应从主状态推导，不要互相打架
- `navVisible` 和 `guideVisible` 不得早于 `handoff`
- `skipRequested` 只能把状态推进到完整 ready，不得停在半成品阶段

## 15. 测试与验收标准

验收时必须按首次进入、站内回访、移动端、fallback 四组场景检查。

### 首次进入

- 首次进入首页时必须播放完整版
- 分镜顺序必须为：
  `闭幕状态 -> 幕布中缝被拉开 -> 戏台显现 -> 暖灯点起 -> 影人登场 -> 导览卡与导航出现`
- opening 完成前，看不到可操作导览卡
- opening 完成前，看不到抢主视觉的解释段落
- opening 最后一帧直接成为首页可浏览状态，不切回模板 Hero

### 站内回访

- 从任一子页返回首页时，不再重播完整版
- 缩短版完成后，三张导览卡顺序仍正确
- 快速多次返回首页时，不会反复打断用户

### 桌面端

- 戏台、暖灯、影人仍是首屏主视觉
- 顶部导航只在 handoff 后可见、可用
- 三张导览卡出现后仍不压住戏台主体

### 移动端

- opening 顺序仍完整可辨认
- 首屏无重叠、无拥挤、无按钮堆积
- 导航为精简形态，但可顺利到达四个路由

### fallback

- reduced motion 下首页可直接使用，且仍保留戏台氛围
- lite 模式不会出现卡死、黑屏或半开幕状态
- 快速返回首页时能够直接进入 ready

### 结构验收

- 首页首屏不再复用当前 `PageHero`
- 首页首屏不再依赖 `SectionBlock` 组织导览
- 首页导览入口顺序固定为 `光影美学 -> 制作工艺 -> 当代新生`
- 首页整体表现为“先入戏，再导览”，而不是“先看说明，再选栏目”
